# 分层中转组网（relay mesh）

## 目标

网关下任意两台设备随时可达、打开就能用，不再绕到洛杉矶的网关中转；设备多了也不至于
每台都要维持 N−1 条隧道。

- **常驻层**：每台设备只常驻连着最近的一两个**中转节点**；中转节点之间两两常驻连通。
  任意两台设备最多经过两个中转就能到达。
- **直连层**：真正要走大流量（文件、远程桌面）时，两端按需打洞直连；打通就把新的流量
  切过去，打不通继续走中转，用户不等。
- 原来的网关中转保留为最后兜底。

## 现状（0.8.9）

- 每台设备跑一个 `muxi-p2p-agent` 应答方（`AgentSidecar`），把别人打进来的流送到本机的
  remote hub（`remote_hub.py`，`ANX-REMOTE/1` + 帧协议，票据由网关签发、一次性）。
- 主动连别人时 `Connector` 为每个目标起一个 `connect` 进程，得到一个本机回环端口；
  按需建立，10 分钟不用就关。隧道是**单向**的：A 连 B 只能 A 开流到 B 的 remote hub。
- 网关中转：`TerminalBridge` / `FilesBridge`，经网关的反向 RPC，慢（几十到几百 KB/s）。

## 角色

**中转节点（relay）**：设备设置 `relay`：`auto`（默认）/ `on` / `off`。`auto` 时满足以下
条件才当中转：

- 能被别人轻松连上：有公网 IP，或 NAT1~3（锥形）。对称型（NAT4）不当中转——两台对称型
  之间互相最难打，让对称型只去连锥形的中转，正好绕开这个难题；
- 常开的机器：服务器、台式机；笔记本不当（`form == laptop` 视为不常开）；
- 设备上报 `relay/1` 特性，附带 NAT 类型。

**普通节点（member）**：其余设备。

网关在设备列表里给出每台的 NAT 类型（取自打洞控制面里它上报的 `n:` 画像）、是否中转、
它当前的"家中转"（见下）。

## 连接维护（客户端负责）

每台设备的管理器里一个 `MeshManager`，启动后：

1. 从网关拿设备列表（在线、特性、NAT、家中转）。
2. **中转节点**：对其他所有在线中转各维持一条常驻隧道（中转之间全连，R 个中转共
   R(R−1) 条单向隧道，R 很小）。
3. **普通节点**：对所有在线中转逐个测往返时延（经隧道发 `ping`），留最近的两个作为
   **家中转**，常驻；其余断开。每 10 分钟重测一次，差距明显（>30%）才换，避免抖动。
4. 隧道是单向的，所以中转也要连回它的成员：中转看到某台设备把自己列为家中转，就对它
   维持一条反向常驻隧道。
5. 常驻隧道不受"10 分钟不用就关"的限制，靠 QUIC 每 5 秒的保活维持。
6. 失败退避：1 → 2 → 4 … 分钟，上限 30 分钟；本机公网出口变化（换网络）时立即重来。
7. 启动时错开：每 2 秒最多新建一条，避免一上来同时打几十个洞。
8. 有公网 IP 的设备之间、同一局域网的设备之间直接连，不需要打洞也不需要中转。

## 选路

打开到设备 T 的终端 / 文件 / 桌面时，按顺序：

1. 已有到 T 的直连隧道 → 直接用。
2. T 是我的家中转或常驻中转 → 直接用那条隧道。
3. 经中转：我的家中转 A、T 的家中转 B（从设备列表得知）。
   - A == B，或 A 与 T 有常驻隧道：我 → A → T；
   - 否则：我 → A → B → T（中转之间全连，最多两跳）。
   多个可选路径时选测得的总往返时延最小的。
4. 对文件和桌面，同时在后台按需打洞直连 T；打通后新开的流走直连。
5. 都不行：网关中转。

## 中转服务（remote hub 新服务 `relay`）

```
ANX-REMOTE/1 {"service": "relay", "ticket": "<中转签发的票据>", "target": "<设备 id>",
              "via": "<下一跳中转 id，可省>"}
```

中转验过自己的票据之后：

- 没有 `via`：用自己到 `target` 的隧道连上它的 remote hub，然后**原样双向转发字节**；
- 有 `via`：向网关要一张 `via` 的中转票据，连到 `via` 的 `relay` 服务，带上
  `{"target": ...}`，再原样转发。

中转只转发字节，不解析内层协议。内层就是调用方和 T 之间的 `ANX-REMOTE` 会话，
由 T 签发的票据鉴权——和直连时一模一样。

上限：每个中转同时转发的流数（默认 32）和总带宽（默认不限，可设）。超限时拒绝，调用方
换下一条路径或回落网关中转。

## 端到端加密

中转会看到内层字节，所以内层必须端到端加密，中转只能看到密文：

- 票据只经网关（TLS）在调用方和 T 之间传递，中转拿不到。
- 经中转的会话用 `ANX-REMOTE/2`：首行只带票据的摘要 `sha256(ticket)[:16]`（T 据此找到
  票据），之后所有帧用 ChaCha20-Poly1305 加密，密钥由票据经 HKDF 派生，两个方向各一把，
  nonce 为递增计数器。
- 直连（QUIC 已经加密）继续用 `ANX-REMOTE/1`，不变。

## 网关侧改动

- 设备列表增加：`nat`（NAT1~4 与分配方式）、`relay`（是否中转）、`home_relays`。
- 新的反向 RPC：设备上报自己的家中转；网关转发给相关中转（让中转建立反向隧道）。
- `remote_ticket` 支持 `relay` 服务。

## 资源与上限

| 规模 | 普通节点常驻隧道 | 中转常驻隧道 |
|---|---|---|
| 10 台（2 个中转） | 2 | 1 + 成员数 |
| 50 台（5 个中转） | 2 | 4 + 成员数（约 20） |

普通节点从 N−1 降到 2；中转的负担随成员数线性增长，所以中转数要随规模增加（大致每
十几台一个）。

## 分阶段落地

1. 中转服务 + 端到端加密 + 手动指定中转的选路（先能用、能测）。
2. `MeshManager`：自动选家中转、常驻、退避、反向隧道。
3. 网关设备列表与家中转上报；界面上显示每台设备当前走的是"直连 / 经 X 中转 / 网关中转"。
4. 后台直连升级。

## 测试

- 中转候选：几台有公网 IP 的服务器（不同地区）。
- 成员：同一局域网的几台台式机、家宽后面的台式机、两台对称型 NAT 后面的笔记本。
- 指标：任意两台建立时延、经中转的往返时延与吞吐（对比网关中转）、中转下线时的切换时间。

## 全网拓扑（`links/1`）

每台设备每 30 秒用 `hub_call links_report` 告诉网关它现在怎样连到其他设备：对端、类型
（直连 / 中转 / 网关 / 打洞中）、经过的中转设备、往返延迟、是否常驻。这次调用本身的往返时间
就是这台设备到网关的延迟，下一次上报时一起带上，设备列表在"在线"旁显示。

网关只保留每台在线设备最近一次上报（超过 120 秒不画），把两端的上报合并成一条边：同一对
设备、同一类型、同一中转只画一条，两端都测到延迟时取平均。网关控制台的"拓扑"页和客户端
设备页的"全网"视角画的就是这张图，有三种画法：

- 拓扑：网关居中，中转设备在内圈，其他设备在外圈按地域分扇区。
- 地图：整个世界（Miller 投影），滚轮或 +/− 缩放，拖动空白处平移，"对准设备"缩放到设备所在范围。
- 地球：正射投影的地球，拖动转动；连线走大圆航线并抬离地面，对端在背面时线翻过地平线。

地图和地球上，网关画在它自己的位置（网关解析自己的公网主机名，查同一个离线 ip2region 库）；
同一地点三台以上的设备合成数字气泡，点开展开，"收起"或"全部收起"还原，放大后会自然分开；
画面外的一组设备合成边缘气泡，点它把地图移过去。定位不出来的设备（内网地址等）放在图下方的
"位置未知"栏里，拖到图上即可设置位置。

客户端设备页的"本机"视角仍然只画本机到每台设备的连接。连接按需建立，两台设备之间没有
线说明还没用过，不是连不上：任何在线设备都能经中转或网关到达。
